# Shared Landing Page Blend

## Purpose

This doc explains how the shared public `/` homepage should combine Leroy's
Lounge and El Roy's Cantina without flattening them into a single generic
hospitality brand.

Use this for:

- root landing-page design
- Stitch handoff and review for `/`
- homepage copy and art direction
- section-level decisions about what should feel shared versus restaurant-specific

Read this after the individual vibe docs:

- `docs/design/leroys-lounge-vibe.md`
- `docs/design/el-roys-cantina-vibe.md`

## Core Rule

The homepage is a shared hub, not a third brand.

It should feel like choosing between two nights out in the same building, not
visiting a parent company website, a hospitality group microsite, or a generic
restaurant directory.

## What The Homepage Must Do

The shared `/` page should help someone answer:

**"Where should I go tonight?"**

That means the page must stay:

- decision-first
- operationally useful
- emotionally specific
- visually premium without becoming abstract

## Brand Relationship

Think of the page as a controlled collision between two worlds:

- Leroy's brings grounded basement-bar warmth, analog grit, and American-bites familiarity.
- El Roy's brings brighter Tex-Mex nightlife, gloss, color, and social energy.

The page should let both identities stay legible at the same time.

## What Not To Do

Do not:

- invent an umbrella brand
- design a parent-company personality
- rename the experience into a third concept
- smooth both restaurants into one neutral minimalist aesthetic
- make one restaurant feel like the real brand and the other feel secondary

## Shared Visual Strategy

The landing page can have a shared frame, but not a shared flattening.

### Shared frame

These can be shared across the page:

- overall scroll rhythm
- section pacing
- structural grid
- common interaction patterns
- dot-nav behavior
- footer placement

### Restaurant-specific identity

These should still shift by restaurant:

- color emphasis
- texture cues
- image treatment
- type tone inside restaurant-owned cards or panels
- supporting copy mood
- badge/accent styling

## Hero Principles

The hero is not a brand statement. It is a choice interface.

### Requirements

- Leroy's on the left for desktop, first on mobile unless a brief explicitly changes that
- El Roy's on the right for desktop, second on mobile unless a brief explicitly changes that
- both options visible immediately
- both cards feel equally intentional
- each card contains:
  - restaurant name
  - current status
  - one explicit Food-menu CTA

### Blend guidance

The hero can use one shared composition, but each half should clearly feel like
its restaurant.

- Leroy's side should feel heavier, warmer, and more analog.
- El Roy's side should feel brighter, glossier, and more electric.

## Section-by-Section Blend Guidance

### Hours

Hours should be the most operationally clear section on the page.

- show both restaurants clearly
- keep the two hours systems distinct
- use atmosphere as framing, not as a replacement for clarity

### Comparison

This section exists to help users choose by food and night-out type.

- start with menu reality first
- Leroy's = American bites
- El Roy's = Tex-Mex
- one short supporting vibe line each is enough

Do not let this section become pure decor language.

### Events

Events can carry more visual flavor and nightlife energy.

- keep restaurant tags clear
- allow more poster/flyer influence here
- "Both" events should feel like shared-building energy, not a new brand identity

### News

News should feel imported and external.

- it is a signal layer, not the site's own magazine
- source, date, and restaurant tag should stay visible
- styling can be atmospheric, but the content model should stay grounded

### Reviews

Reviews should feel like paired proof.

- one Leroy's review plus one El Roy's review per carousel turn
- tone should feel credible and lived-in
- avoid fictional-editorial voice

## Palette Relationship

The page should not default to clean white modern editorial surfaces unless a
task-specific brief explicitly asks for it.

Prefer a shared neutral base that can absorb both worlds:

- tobacco darks
- aged cream
- warm black
- oxidized metallics
- muted paper and wall tones

Then let each restaurant push into the shared frame differently:

- Leroy's pushes amber, walnut, brass, oxblood
- El Roy's pushes agave green, lacquer red, neon peach, chrome, cream stucco

## Typography Relationship

Shared typography can work, but it should flex in tone.

- Leroy's moments can feel heavier, sign-like, analog, condensed, or worn-in.
- El Roy's moments can feel bolder, glossier, sharper, more poster-like.

Avoid a single polished editorial serif system becoming the whole personality of
the homepage.

## Texture And Image Rules

The shared homepage should feel physical.

Use:

- grain
- halation
- print wear
- glow
- signage cues
- tactile surfaces

Avoid:

- generic stock restaurant photography as the full identity
- SaaS-clean flat gradients as the dominant mood
- synthetic "luxury" polish that erases both venues

When a brief requires the real sign assets, those are the main identity anchors.
Texture and atmosphere should support them, not replace them.

## Copy Tone

Shared-page copy should sound like a confident local host, not a luxury brand
manifesto and not a fictional magazine editor.

Good shared-page copy is:

- concise
- directional
- specific
- lightly atmospheric

Bad shared-page copy is:

- overwritten lore
- invented brand mythology
- abstract "experience design" language
- vague prestige copy

## Motion

The page can feel premium and scroll-driven, but motion should not overpower the
content.

- use restrained reveals
- favor pacing and hierarchy over spectacle
- keep motion compatible with a real operational homepage

## Decision Filter

When judging a shared homepage design, ask:

1. Does this still feel like Leroy's and El Roy's, or did it turn into a third brand?
2. Can a user choose a restaurant quickly?
3. Is the operational information still obvious?
4. Does the page feel like two distinct nights out in one building?
5. Would this still make sense once real admin-driven hours, events, news, and reviews are flowing through it?

If the answer to any of those is "no," the design needs correction before
implementation.
