Full security audit completed 2026-03-21 on branch v0.5.2 (auditing v0.5.4 auth additions).

**Critical: SSRF in /api/firebase-write.js** — client-supplied `fbUrl` is used to construct a server-side fetch that appends `FIREBASE_SECRET` as a query param. Authenticated manager/admin can exfiltrate the secret.

**High: Stored XSS via cat.icon** — `cat.icon` from Firebase is rendered via innerHTML without escHtml() on lines 379, 760, 1241, 1654. Public viewers are affected via line 760.

**High: cat.id attribute injection** — Firebase-sourced category IDs interpolated into onclick handlers without escaping, allowing JS injection.

**Why:** These are the highest-priority items. The SSRF is exploitable by any authenticated manager. The XSS vectors require admin/manager write access to Firebase but affect all public visitors.

**How to apply:** Watch for regressions on these specific patterns in future PRs. Any new innerHTML usage must use escHtml(). Any new inline event handlers with interpolated data must escape the values. The firebase-write endpoint must not accept URLs from the client.
